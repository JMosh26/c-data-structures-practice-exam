# P2 — Vault Codes

| | |
|---|---|
| **Topic** | Closed hashing (quadratic probing) |
| **Difficulty** | Medium |
| **Points** | 35 |
| **Time limit** | 1.0 s |
| **Memory limit** | 64 MB |

## Description

A vault has `M` numbered slots and resolves collisions with **quadratic probing**. For
a code `k`, the home slot is

```
h(k) = ((k mod M) + M) mod M
```

and the probe sequence is

```
(h(k) + 0^2) mod M, (h(k) + 1^2) mod M, (h(k) + 2^2) mod M, ...
```

Only `M` probes are attempted. Notice that the step is squared and then added; this is
**not** `(h(k) + step)^2`.

For each arriving code:

1. Search its probe sequence for a duplicate. Stop at the first empty slot, at the code
   itself, or after `M` probes.
2. If the code is found, report the duplicate and do **not** insert it.
3. Otherwise insert it into the first empty slot on the sequence and print the slots that
   were visited, in order.
4. If no empty slot is found in `M` probes, the insertion fails and the printed path ends
   with `FAIL`.

Count a probe for every slot examined. The reported total includes both the duplicate
search probes and the insertion probes.

## Input Format

- The first line contains two integers, `M` and `N`.
- The next `N` integers are the codes. They may be spread across one or more lines.

## Output Format

For each code, print one line:

- Duplicate: `k: DUP at slot`
- Inserted: `k: s0 -> s1 -> ... -> sN`
- Failed: `k: s0 -> s1 -> ... -> FAIL`

There is one space after the colon and one space on each side of `->`, with no trailing
spaces. After all codes, print:

```
table:
```

followed by exactly `M` lines (`i: key` or `i: empty`), and finally:

```
probes: total
```

## Constraints

- `1 ≤ M ≤ 1000`
- `0 ≤ N ≤ 10000`
- `-10^9 ≤ key ≤ 10^9`

## Sample Input 1

```text
7 5
0 7 14 7 21
```

## Sample Output 1

```text
0: 0
7: 0 -> 1
14: 0 -> 1 -> 4
7: DUP at 1
21: 0 -> 1 -> 4 -> 2
table:
0: 0
1: 7
2: 21
3: empty
4: 14
5: empty
6: empty
probes: 22
```

## Explanation

Every code here has home slot `0`.

| Code | Search probes | Insert probes | Output | Running total |
|------|---------------|---------------|--------|---------------|
| 0 | 1 (slot 0 empty) | 1 (slot 0) | `0: 0` | 2 |
| 7 | 2 (slots 0, 1) | 2 (slots 0, 1) | `7: 0 -> 1` | 6 |
| 14 | 3 (slots 0, 1, 4) | 3 (slots 0, 1, 4) | `14: 0 -> 1 -> 4` | 12 |
| 7 | 2 (slots 0, 1) | — | `7: DUP at 1` | 14 |
| 21 | 4 (slots 0, 1, 4, 2) | 4 (same path) | `21: 0 -> 1 -> 4 -> 2` | 22 |

The quadratic steps visit slots `0`, `1`, `4`, `2`, ... modulo 7.

## Hints

1. A helper that follows the probe sequence and records the path keeps the two phases
   consistent.
2. Reset the path length before each insertion.
3. Use `(long long)step * step` to make the intent explicit and avoid overflow on other
   platforms.
4. When `M = 1`, the only probe is slot `0`.
5. Remember that the duplicate search stops at the first empty slot; it does not need to
   scan the whole table.
