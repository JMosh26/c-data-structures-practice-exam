# P3 — Ghost Gallery

| | |
|---|---|
| **Topic** | Closed hashing (double hashing with tombstones) |
| **Difficulty** | Medium |
| **Points** | 35 |
| **Time limit** | 1.0 s |
| **Memory limit** | 64 MB |

## Description

A gallery has `M` numbered slots and uses **double hashing**. Deleted exhibits leave
behind **tombstones** so that later searches do not stop too early.

The two hash functions are

```
h1(k) = ((k mod M) + M) mod M
h2(k) = 1 + (((k mod (M - 1)) + (M - 1)) mod (M - 1))
```

`h2(k)` is always in the range `1 .. M - 1`, so it is never zero. The probe sequence is

```
(h1(k) + i * h2(k)) mod M    for i = 0, 1, ..., M - 1
```

Each slot is in one of three states: **empty**, **occupied**, or **tombstone**.

Process `Q` commands:

| Command | Meaning |
|---------|---------|
| `ADD k` | Insert `k` if it is not already live. |
| `DEL k` | Delete the live key `k`, leaving a tombstone. |
| `HAS k` | Report whether `k` is live. |
| `COUNT` | Print the number of live keys. |
| `PRINT` | Print every slot and its state. |

Insertion rules:

- If the key is already live, print `EXISTS`.
- Otherwise probe the sequence. Remember the **first tombstone** you pass.
- If you reach an empty slot, insert into the remembered tombstone if there was one,
  otherwise into the empty slot.
- If the whole sequence is full and a tombstone was seen, reuse that tombstone.
- If no place is available, print `FULL`.

## Input Format

- The first line contains two integers, `M` and `Q`.
- The next `Q` lines each contain one command and, for `ADD` / `DEL` / `HAS`, one
  integer key.

## Output Format

- `ADD k` prints `ADDED slot`, `EXISTS`, or `FULL`.
- `DEL k` prints `DELETED slot` or `MISSING`.
- `HAS k` prints `YES slot` or `NO`.
- `COUNT` prints the number of live keys.
- `PRINT` prints exactly `M` lines:
  - `i: key` for an occupied slot,
  - `i: tomb` for a tombstone,
  - `i: empty` for an empty slot.

## Constraints

- `2 ≤ M ≤ 1000`
- `0 ≤ Q ≤ 10000`
- `-10^9 ≤ key ≤ 10^9`

## Sample Input 1

```text
7 12
ADD 10
ADD 17
ADD 24
HAS 17
DEL 17
HAS 17
ADD 31
COUNT
PRINT
DEL 99
ADD 24
COUNT
```

## Sample Output 1

```text
ADDED 3
ADDED 2
ADDED 4
YES 2
DELETED 2
NO
ADDED 5
3
0: empty
1: empty
2: tomb
3: 10
4: 24
5: 31
6: empty
MISSING
EXISTS
3
```

## Explanation

For `10`, `h1 = 3` and `h2 = 5`, so it lands in slot `3`.

For `17`, `h1 = 3` and `h2 = 6`: slot `3` is occupied, then slot `2` is empty, so it is
inserted at `2`.

For `24`, `h1 = 3` and `h2 = 1`: slot `3` is occupied, then slot `4` is empty.

`DEL 17` turns slot `2` into a tombstone. A later `HAS 17` follows the same path: slot
`3` is occupied by `10`, slot `2` is a tombstone (keep going), and slot `1` is empty, so
the answer is `NO`.

`ADD 31` hashes to slot `3` and probes slot `5` next, which is empty, so the tombstone at
slot `2` is not reused. The tombstone remains visible in `PRINT`.

## Hints

1. Store the state separately from the key so that any integer key is allowed.
2. Normalize both modulo operations; negative keys are legal.
3. `find_slot` must continue past tombstones but stop at an empty slot.
4. In `insert_key`, record the first tombstone but keep probing until an empty slot or a
   matching live key is found.
5. `h2` is computed modulo `M - 1` and then shifted by 1.
6. The live count changes only on a successful `ADD` or `DEL`.
