# P3 — Double Trouble

| | |
|---|---|
| **Topic** | Closed hashing (double hashing) |
| **Difficulty** | Medium |
| **Points** | 35 |
| **Time limit** | 1.0 s |
| **Memory limit** | 64 MB |

## Description

A table with `M` slots uses **double hashing** to spread collisions:

```
h1(k) = ((k mod M) + M) mod M
h2(k) = 1 + (((k mod (M - 1)) + (M - 1)) mod (M - 1))
slot  = (h1(k) + i * h2(k)) mod M    for i = 0, 1, ..., M - 1
```

Because `h2(k)` is never `0`, the probe sequence always takes a non-zero step. Insert
`N` keys in order:

1. If the key is already in the table, ignore it. (Ignoring a duplicate does not probe.)
2. Otherwise try the probe sequence. Place the key in the first empty slot.
3. If all `M` probes fail, print `FAILED <key>`.

After all insertions, print the table.

## Input Format

```
M N
k1 k2 ... kN
```

## Output Format

1. One `FAILED <key>` line for each rejected key, in insertion order.
2. `M` table lines:
   - Occupied: `i: key`
   - Empty: `i: (empty)`

## Constraints

- `2 ≤ M ≤ 1000`
- `0 ≤ N ≤ 2M`
- `-10^9 ≤ key ≤ 10^9`

## Sample Input 1

```text
7 4
10 17 24 31
```

## Sample Output 1

```text
0: (empty)
1: (empty)
2: 17
3: 10
4: 24
5: 31
6: (empty)
```

## Explanation

All four keys hash to `h1 = 3`. Their steps are:

| Key | `h1` | `h2 = 1 + key mod 6` | Probe sequence | Final slot |
|-----|------|-----------------------|----------------|------------|
| 10 | 3 | 1 + 4 = 5 | 3 | 3 |
| 17 | 3 | 1 + 5 = 6 | 3, 2 | 2 |
| 24 | 3 | 1 + 0 = 1 | 3, 4 | 4 |
| 31 | 3 | 1 + 1 = 2 | 3, 5 | 5 |

## Hints

1. `M - 1` is a divisor in `h2`, so guard against `M = 1`; the constraints already
   guarantee `M ≥ 2`.
2. Normalize negative remainders before computing `h2`, otherwise the step can become
   zero or negative.
3. Use `long long` for `i * h2` if you want extra safety; with `M ≤ 1000` it is not
   strictly necessary.
4. Check for duplicates before probing.
