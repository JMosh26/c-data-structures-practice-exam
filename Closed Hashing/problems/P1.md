# P1 — Linear Probing Lot

| | |
|---|---|
| **Topic** | Closed hashing (open addressing, linear probing) |
| **Difficulty** | Easy |
| **Points** | 30 |
| **Time limit** | 1.0 s |
| **Memory limit** | 64 MB |

## Description

A parking lot has `M` numbered spaces and uses a hash table to record which car is in
which space. Collisions are resolved with **linear probing**.

Insert `N` integer keys into the table in the given order. Use:

```
h(k)  = ((k mod M) + M) mod M
slot  = (h(k) + i) mod M    for i = 0, 1, 2, ...
```

Place the key in the first empty slot found. If the key is already in the table, ignore
the duplicate. It is guaranteed that the distinct keys always fit in the table.

After all insertions, print the table from slot `0` to slot `M - 1`.

## Input Format

- The first line contains two integers, `M` and `N`.
- The next `N` integers are the keys. They may be spread across one or more lines.

## Output Format

Print exactly `M` lines:

- Occupied slot: `i: key`
- Empty slot: `i: (empty)`

## Constraints

- `1 ≤ M ≤ 1000`
- `0 ≤ N ≤ M`
- `-10^9 ≤ key ≤ 10^9`

## Sample Input 1

```text
7 5
10 20 15 7 22
```

## Sample Output 1

```text
0: 7
1: 15
2: 22
3: 10
4: (empty)
5: (empty)
6: 20
```

## Explanation

| Key | `h(k)` | Probes | Final slot |
|-----|--------|--------|------------|
| 10 | 3 | 3 | 3 |
| 20 | 6 | 6 | 6 |
| 15 | 1 | 1 | 1 |
| 7 | 0 | 0 | 0 |
| 22 | 1 | 1 → 2 (occupied) | 2 |

`22` hashes to slot `1`, but `15` is already there, so linear probing moves it to slot
`2`.

## Hints

1. Keep a separate `used[]` array (or a sentinel value outside the key range) so you can
   tell an empty slot from a stored key.
2. Wrap around with `% M`.
3. Check for duplicates before probing, or the same key may be inserted twice.
