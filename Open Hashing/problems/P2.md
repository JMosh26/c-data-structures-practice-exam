# P2 — Lost and Found

| | |
|---|---|
| **Topic** | Open hashing (separate chaining) |
| **Difficulty** | Medium |
| **Points** | 35 |
| **Time limit** | 1.0 s |
| **Memory limit** | 64 MB |

## Description

A lost-and-found office stores item IDs in a hash table with `M` buckets. Collisions
are handled with **separate chaining**, and new keys are appended to the end of their
chain.

Build the table from `N` keys, then answer `Q` search queries. Use:

```
h(k) = ((k mod M) + M) mod M
```

If a key is already present, ignore the duplicate insertion.

For each query, search only the chain for `h(k)`. If the key is found, report its
bucket and its **1-based position** in that chain (the first node has position `1`).
Otherwise report `NOT FOUND`.

## Input Format

```
M N
k1 k2 ... kN
Q
q1 q2 ... qQ
```

The `N` keys and the `Q` queries may each be spread across several lines.

## Output Format

For each query, print one line:

- `FOUND <bucket> <position>`
- `NOT FOUND`

## Constraints

- `1 ≤ M ≤ 1000`
- `0 ≤ N ≤ 10000`
- `0 ≤ Q ≤ 10000`
- `-10^9 ≤ key, query ≤ 10^9`

## Sample Input 1

```text
5 7
12 7 19 5 22 7 3
5
22 7 9 3 5
```

## Sample Output 1

```text
FOUND 2 3
FOUND 2 2
NOT FOUND
FOUND 3 1
FOUND 0 1
```

## Explanation

The table is the same as in P1:

```
0: 5
1: (empty)
2: 12 -> 7 -> 22
3: 3
4: 19
```

- `22` is the third node of bucket `2` → `FOUND 2 3`
- `7` is the second node of bucket `2` → `FOUND 2 2`
- `9` would hash to bucket `4`, whose chain contains only `19` → `NOT FOUND`
- `3` is the first node of bucket `3` → `FOUND 3 1`
- `5` is the first node of bucket `0` → `FOUND 0 1`

## Hints

1. Reuse the insertion code from P1.
2. Start the position counter at `1` and increment it after each node you visit.
3. Stop as soon as you find the key; do not keep counting.
